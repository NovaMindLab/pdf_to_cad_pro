## 2. 核心转换引擎 (Python Sidecar) 深度重构

### 2.1 原生圆与圆弧最小二乘识别算法 (`fit_circle` / `fit_arc`)
传统工具将 PDF 的贝塞尔曲线采样点粗暴连接为 `LWPOLYLINE`，导致变电站接线图上的断路器符号、线圈符号充满多边形锯齿。

`converter/converter.py` 引入圆拟合数学模型：
1. **构建正规方程组**：设圆方程为 $(x - a)^2 + (y - b)^2 = R^2$，展开为线性方程：
   $$2ax + 2by + c = x^2 + y^2 \quad (c = R^2 - a^2 - b^2)$$
2. **最小二乘解算**：通过离散点集解超定矩阵方程，计算出理论圆心 $(cx, cy)$ 与理论半径 $R$；
3. **方差校验**：计算所有采样点到理论圆心的距离标准差 $\sigma_R$。当满足严格约束：
   $$\frac{\sigma_R}{R} < 0.08$$
   判定该曲线为标准几何圆；
4. **闭合回路与圆弧分流**：
   - 若起始点与终止点欧氏距离小于 3 且角度覆盖近乎一周，调用 `msp.add_circle((cx, cy), radius=R)`；
   - 若未闭合，计算起始与终止采样点的反正切角，转换为 CAD 标准角度输出 `msp.add_arc((cx, cy), radius=R, start_angle=s, end_angle=e)`。

> **实测效果**：在变电站一次系统图 `[BA22015S-U0101-04]` 中，成功直接识别拟合出 **50 个 AutoCAD 标准原生圆**。

### 2.2 24位 TrueColor 与 AutoCAD ACI 双轨色彩体系
- **PDF 颜色提取**：解析路径与字符的 `non_stroking_color` 和 `stroking_color`，将其归一化并转为 24 位整型：
  $$\text{TrueColor} = (R \ll 16) + (G \ll 8) + B$$
- **AutoCAD 双轨兼容**：
  - DXF 组码 `420`：写入 24-bit TrueColor 数值（现代 AutoCAD 2004+ 与国产 CAD 高保真显示）；
  - DXF 组码 `62`：通过色彩欧氏距离空间匹配最接近的标准 ACI 调色板索引（老旧 CAD 系统兜底）。

### 2.3 文字重叠彻底根除与角度旋转排版 (`rotation`)
- **根除重叠**：重构 `group_rotated_chars_into_words`，将原本基于静态全局间距的判断改为基于当前字符自身变换矩阵法向量的投影距离判断，彻底防止多行或相邻标注文字误合并；
- **逆时针角度转换**：
  - PDF 视口 $Y$ 轴向下，旋转矩阵输出的角度为顺时针方向；
  - CAD DXF 组码 `50` 坐标系 $Y$ 轴向上，旋转定义为逆时针方向；
  - 核心换算公式：
    $$\theta_{\text{CAD}} = (-\theta_{\text{PDF}}) \pmod{360}$$
- **实测验证**：在测试图纸 `[BA22015S-U0101-02]` 中成功识别 **14 处沿电缆倾斜排布标注**，转换后的文字与线缆角度绝对平行对齐。

### 2.4 智能光栅扫描件拦截机制
针对用户误将手机拍照或扫描生成的“纯位图 PDF”导入转换导致结果为空的困惑，系统在解析初阶段自动统计矢量图元与位图图元面积。当检测到位图面积 $>80\%$ 且矢量图元 $<10$ 时，立即拦截并弹出友善提示：“检测到当前文件为纯光栅扫描件，请使用矢量 PDF 转换以获得最佳 CAD 效果”。

## 3. 前端 CAD 查看器与交互全链路升级

### 3.1 浮动图层控制面板 (`#layer-control-panel`)
- **位置与形态**：悬浮于 CAD 画布右上角的暗色毛玻璃控制面板，支持一键折叠为小胶囊图标；
- **动态图层感知**：解析 DXF 时自动提取所有出图图层（LINES、RECTS、CIRCLES、ARCS、TEXTS、SYMBOLS 等），并显示各图层的图元数量及对应颜色指示块；
- **毫秒级显隐切换**：勾选/取消复选框时，调用 `threeCadEngine.setLayerVisibility(layer, visible)`，直接切换 GPU 批处理网格的 `visible` 状态并重绘，性能损耗为 0。

### 3.2 WebGL Three.js 原生几何渲染管线
- **圆与弧细分光栅化**：`buildDxfScene` 原生支持 CIRCLE 与 ARC，根据半径大小动态自适应细分步长（16~64 段），确保在大倍率缩放时圆弧依然平滑无棱角；
- **带角度文本 3D 渲染**：`createTextMesh` 支持局部旋转矩阵偏移，使得 Three.js 视口中倾斜文字的渲染角度与 CAD 软件完全一致；
- **交互与编辑闭环**：
  - 悬停与选中高亮（`hoverLine` / `selectedLine`）自动根据圆半径与弧度生成几何高光环；
  - 夹点捕捉（`gripPoints`）自动提取圆心、四极点与弧线两端端点作为捕捉目标；
  - 内置编辑器修改属性后重新导出 DXF 时，`writeEntity` 完整输出原生 `CIRCLE`、`ARC` 及文字 `rotation` 组码。

## 4. 打包工程瘦身与差分更新部署

### 4.1 根除 Python 二进制双重重复打包
- **问题定位**：此前 `package.json` 的 `build.files` 字段配置了 `["**/*"]`，导致 electron-builder 在打包时把 `converter/dist/pdf-converter.exe`（49MB）一并压进了 `app.asar`，而 `extraResources` 配置又在外层拷贝了一份，形成了双重冗余，使 `app.asar` 膨胀到 88MB，安装器达到 189MB。
- **解决方案**：在 `build.files` 中显式排除 `!converter/dist/**`，并在 `main.js` 中适配双重探测路径。
- **成效**：
  - `app.asar` 由 **88 MB** 缩减至 **37.4 MB**（瘦身 **57%**）；
  - 差分更新补丁由 **50+ MB** 缩减至 **16.3 MB**（瘦身 **70%**）；
  - 完整安装包由 **189 MB** 缩减至 **134.3 MB**。

### 4.2 部署脚本流式上传提升 (`auto_deploy/deploy.js`)
- 部署工具改造为优先调用本机 `gh.exe`（GitHub CLI）执行 `gh release upload <tag> <files> --clobber`；
- 利用 Go 底层流式断点续传，彻底摆脱 Node.js 单次发包 100MB+ 内存 Buffer 容易遭遇 `fetch failed` 的网络限制。
